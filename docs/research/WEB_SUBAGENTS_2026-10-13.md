## Ownership and implementation boundary

Pi Sessions own identity, provider/model selection, trust, tools, cancellation and parent lifecycle. The existing subagent manager and workflow AgentRecord own execution facts; the Web observer registry supplies bounded read-only projections. The transcript, overview, child list and detail are views of those facts. Presentation restoration is scoped by exact Session ID and path and never restores authority or a running task.

The change should strengthen these existing seams: compact task rows, shared identity avatar, saved-state recovery and existing child inspection. No new model-facing tool, setup preference, keyword executor or orchestration workflow is needed. Codex's parent notification policy is reference evidence, not a replacement for OpenPI's explicitly adopted event delivery.

This change adopts Codex's **read-only inspection path**. Its `canInteract:true` branch opens a separate child tab with a composer and writer-conflict handling; that branch is not copied here. Parent/child communication continues through Pi's existing `subagent_send`, `subagent_cancel`, `subagent_check`/`wait` and completion inbox. Existing user-owned BTW actions retain their own authority. Workflow inspection does not acquire write permission or reconstruct a child Session.

## OpenPI implementation chain

- Autonomous and keyword-loaded Direct: `capability-intent.ts` exposes guidance/tools → existing `subagent_spawn` → `PiSession`/manager → existing Web provider → `Transcript.familyCard` → `SubagentTaskRow`. Exact child ID and current controlled parent determine live status; saved terminal receipts recover status after manager loss.
- Workflow: existing `AgentRecord` → `projectWorkflowCapability.children` → the same overview/list/row → `workflowAgentDetail` → existing `kind=workflows` provider detail. Exact identity is `${runId}:call:${index}`. The existing owner retains or evicts evidence; this view never reads journals from disk. Unknown outcome overrides legacy state; owner errors such as result-persistence failure cannot be hidden by child execution success.
- Open: exact selected parent ID/path + child ID/kind → `SubagentPanel` → existing capability-detail route → current Session's provider. Cross-Session/child/kind replies are rejected, inactive reads are aborted, and failed refreshes retain the last detail with a stale warning.
- Parent → child: existing send/stop tool evidence remains a distinct disclosure and names the actual child. Successful send invalidates earlier saved terminal state even when the acknowledgement still samples the old asynchronous manager snapshot. New terminal evidence must come from a later child record.
- Child → parent: existing completion inbox delivers the original result once. Compact result rows retain immutable receipt status and the original batch evidence; historical parent text is not rewritten. Current task rows use the latest exact child projection.
- Refresh: a tab-local, bounded presentation record retains only parent ID/path. Reload restores the overview after exact scope matching, clears selected detail, and never restarts work. Return within the same mounted panel retains list scroll and child disclosure state.
- Appearance: 16px OpenPI-owned seeded geometric avatars in transcript rows, 24px in list/detail; normal weight task name and adjacent neutral state. Hover and keyboard focus are separate. Coarse/no-hover targets are at least 44px; narrow mouse rows remain compact. Long list titles truncate while preserving the complete accessible name and title hint.
