## Implemented ownership

Settings → Web search starts the canonical `/openpi-setup` episode. Its existing parent-only writer admits one fixed optional-package action, alone: choose Exa for a new profile, preserve an existing profile, or disable native user resources. Native confirmation precedes mutation. Pi's package manager installs the exact source; installed manifest identity and persisted native settings are checked. No second installer, credential store, search provider implementation, persistent enable flag, model-facing web wrapper, or capability group is introduced.

TUI review uses `ctx.ui.confirm`. Web review uses the existing `ask_user` Session bridge and controller-bound question broker, inside the same configuration tool call. Only the exact affirmative choice without an additional note authorizes mutation. Cancellation, expiry, dismissal, custom text, and an absent bridge fail closed. This does not mark print-mode Sessions as generally dialog-capable or add a new question transport.

An explicitly selected Exa profile is exclusively created at private permissions before installation. It limits search to Exa, uses native dynamic activation and direct HTTP/PDF reading, defaults to raw search results, and disables source-check orchestration, cookie access, Git cloning, image/video processing, and hosted page extraction. The native tool still allows model-selected per-call summary workflows; the profile is not an enforcement boundary against every additional model call. Existing preferences are never rewritten. Configuration and current Session loading remain separate; no automatic reload occurs. The package is excluded by native source/manifest identity from children before import, including renamed tools. Another installed source with the same package identity is rejected instead of silently duplicated.

Automatic summary/source-check orchestration is omitted from the selected profile; the original-image replay passes using orthogonal search/read primitives. ### Implemented boundary

`extensions/web-search/` uses `before_provider_request` to add a hosted tool to an explicitly enabled, supported current connection. Official defaults cover reviewed model identities; unrecognized models/endpoints fail closed. A setup declaration is scoped to the exact provider, model, API and base URL, and requires explicit capability confirmation or actual native-search verification. The known DeepSeek endpoint cannot be force-enabled. The current model, ordinary tools and Pi credential source remain unchanged. No provider client, alternate credential store, local search tool, fixed fact-checking workflow, cache, or new capability group is introduced.

Pi's `provider_stream_event` exposes native evidence before normalization. `message_end` replacement preserves bounded opaque provider output and clickable citations on the assistant message before persistence. Subsequent requests replay only retained messages for the identical connection, preserving ordinary function-call/result pairing. Disabling search stops offering the hosted tool and preserves history. Context compaction, usage and cancellation remain Pi-owned. The extension is excluded from Direct/Workflow children because hosted tools would otherwise bypass their local tool allowlists. Hook exceptions alone are insufficient in Pi: explicit abort plus an error terminal message is necessary to prevent a conflicted request from continuing.

The canonical setup fields are `webSearch.enabled` and `webSearch.modelSupport`; the episode writer exposes `web_search_enabled` and a declaration for the current connection. Web settings show the on/off preference independently of current-model readiness. They do not select or install Exa. The transcript projects actual native call status and bounded query text separately from local tools; a textual claim to have searched is not evidence. The legacy reviewed package installer remains available only for explicit optional-package management, with its existing review contract.
