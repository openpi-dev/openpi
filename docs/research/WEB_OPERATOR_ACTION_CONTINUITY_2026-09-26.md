## Interaction Choices

1. **Questions keep operator intent, not native terminal state.** The App owns a renderer-only cache keyed by exact Session id/path/requestId. It retains options, custom answers, notes, question/review position, and the original uncertain answer or dismissal. Native pending null or a successor retires the old form; no local answered/cancelled fact is invented. Returning to the same pending request can only recheck the same original payload. A synchronous submission lock prevents same-tick duplication; unmount aborts client waiting, not native execution. Canonical reads synchronously update the current request identity, so an old receipt cannot overwrite a successor or null before React unmounts the old form.
2. **Only submitted answers are validated.** Oversized inactive custom text or option notes remain editable but do not invalidate another selected answer. The native UTF-8 answer limit still governs the actual payload. Question draft memory is limited to 32 nonempty request positions and 1 MiB UTF-8 text; new content over capacity is rejected, older text is never silently evicted, and shrinking/clearing can recover capacity. An uncertain dismissal also occupies a slot. At slot saturation a new dismissal is rejected before transport, with feedback; this is a deliberate UI resource boundary, not an unchanged submission guarantee or a native failure.
3. **A rename stays visible until known settlement.** Pending input/save/cancel are locked, with a synchronous duplicate guard. Failure preserves the text and reports inside the dialog. An archived rename re-reads the same query through native cursors up to the previously opened range; failed refresh retains prior rows and range for retry. Query/view changes reject late pages. Metadata writes never acquire Session control.
4. **Removal and creation describe their real effects.** Workspace removal is consistently named Remove from sidebar, displays the full path, retains the confirmation's native file/Session-preservation semantics, and waits for the native result. A later snapshot read failure does not turn a successful write into failure. Both New Session entrances return to Current and clear search only after a matching native id/path/workspace receipt. Cancellation, chooser-only preparation, failure, and a newer filter/view intent preserve the old list. An existing scope-ref token detects changing away and back; an empty native Session is not claimed to appear immediately in persisted rows.
5. **Search remains usable while unrelated state advances.** Complete catalogs filter locally; truncated catalogs use the existing bounded search API. Ordinary snapshot updates preserve the pending/result state. Accepted catalog/control/selection changes and native runtime/settings invalidations cancel stale results using the existing request generation/AbortController. The existing settings event covers edits to hidden models whose bounded snapshot and omitted count do not change. Search errors have an explicit retry icon. ArrowDown enters results, ArrowUp from the first row returns to search, Home/End navigate rows, and Escape closes only the picker. Composition does not navigate or close it. Exact native file authority disables and closes a revoked picker.
6. **Completion preserves normal editing navigation.** Only plain Tab on an available Slash command completes it; modified Tab and unavailable choices retain browser focus navigation. A file dialog captures the exact owner, revision, and selection range. A valid same-draft result replaces that range, preserves the path's original spelling, and encodes only the existing artifact-reference API input. Rejected/stale insertion leaves the dialog path and error visible. No file index, search service, writable grant, or new context protocol was added.
