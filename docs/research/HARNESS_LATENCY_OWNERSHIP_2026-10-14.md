## Question and evidence boundary

Which generally useful speed improvements can OpenPI implement through Pi extensions, which require native Pi changes, and which belong to the model gateway? This investigation reads implementations rather than treating an issue proposal, UI appearance or available feature flag as proof of deployed behavior.

The resident runtime was independently checked at OpenPI `625d4aae`; with its actual agent directory and Node 24, `pi list` reported one OpenPI source, the resident checkout. This establishes current provenance, not the version that produced an earlier failure. No model request, runtime configuration change or service restart was performed for this research.

The earlier private trace took 21m36s with 73 ordinary model responses. A later repair/commit turn took 17m32s with 41 responses and 34 Code Mode calls containing 103 nested calls. Different tasks, repository state, model latency and upstream load prevent a causal speedup claim. The later turn returned approximately 376K text characters to the model, reached 112K context tokens, and spent approximately 59s compacting. Those observations justify investigating output and round trips; they do not establish an optimal output budget.

A separate push turn spent 399s in one failed model response. Its exact gateway request recorded an upstream 503 and an internal retry before HTTP 200 and the client's malformed-SSE error. The preceding push tool had succeeded. Raw malformed SSE bytes were not retained, so the producing hop remains unknown. The matched requests do not support attributing minutes of additional local dispatch/serialization to OpenPI.

## Findings

### 1. Parallel batching already exists; streaming overlap is a different primitive

Pi's [agent loop](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/agent/src/agent-loop.ts#L241) awaits the complete assistant response before executing its tool batch. It supports parallel ordinary calls, unless sequential configuration or a sequential tool requires the batch to run sequentially. Native Code Mode also lets the model compose independent calls and filter their results. OpenPI's default activation therefore fixes availability; it does not introduce parallel execution for the first time.

Codex uses a [parallel admission gate](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/tools/parallel.rs#L213) that permits parallel-safe tools concurrently and gives other tools exclusive admission. The Claude reconstruction [query loop](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/src/query.ts) can dispatch a completed tool block while the remaining model stream continues; its [scheduler](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/src/services/tools/StreamingToolExecutor.ts#L131) validates concurrency safety and fails closed on classification errors. Its local streaming flag defaults on, subject to overrides. Its own [fallback warning](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/src/services/api/claude.ts#L2589) identifies duplicate execution after a partial stream followed by a replacement request.

**Inference:** reducing avoidable model round trips is an immediate model-use opportunity. Starting tools before the final response requires Pi-owned authority, cancellation, partial-response persistence and replay semantics. An OpenPI second scheduler would duplicate that ownership. Neither concurrency metadata nor a read-only command classifier proves arbitrary Bash independence. Maka's [resource scheduling issue #4487](https://github.com/apache/maka/issues/4487) remains open.

### 2. Long work must keep its process or cell identity

Codex [exec_command](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/tools/handlers/unified_exec.rs#L65) normally yields after 10s and supports later `write_stdin` against the existing process identity. Its [process manager](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/unified_exec/process_manager.rs#L606) retains live sessions and distinguishes process exit from completed output collection. Code Mode also has [yielded cells](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/tools/code_mode/execute_handler.rs#L145) and a [wait/terminate contract](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/tools/code_mode/wait_spec.rs#L8). Yielding is distinct from a timeout that kills work.

The Claude reconstruction [background transition](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/packages/builtin-tools/src/tools/BashTool/BashTool.tsx#L1031) retains the same shell handle rather than launching the command again. Its special 15s automatic-background rule requires KAIROS assistant mode; it is not a universal default. Maka's [Bash contract](https://github.com/apache/maka/blob/d6a5b99ba0f557e4bd27a5a64c4988d3cbf7f4be/packages/runtime/src/shell-tools.ts#L260) uses explicit background selection, despite an earlier RFC discussing automatic promotion.

OpenPI already has [background terminals](https://github.com/openpi-dev/openpi/blob/625d4aae5b9b347161079dbbae62a3a5ad583852/extensions/background-terminals/index.ts): stable IDs, bounded status output, logs, stop/watch and coalesced exit notifications. Their [contract](https://github.com/openpi-dev/openpi/blob/625d4aae5b9b347161079dbbae62a3a5ad583852/extensions/background-terminals/src/prompt.ts#L33) explicitly provides no stdin. Package tools are progressively loaded; existence on disk does not establish exposure in a historical model request. Pi's native [Code Mode execution](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/coding-agent/src/extensions/codemode/execute.ts#L500) awaits its sandbox and closes it on completion, rather than exposing Codex's resumable-cell contract.

**Recommendation:** inspect actual tool availability and use existing background terminals for independent long builds/tests. Automatic adoption of an already-running native Bash process, PTY continuation or resumable native Code Mode cells needs a supported Pi process/cell lifecycle. Do not implement continuation by rerunning a command after timeout.

### 3. Output offload exists; useful budgets and faithful errors still matter

Pi [Code Mode](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/coding-agent/src/extensions/codemode/execute.ts#L250) defaults to approximately 10K output tokens, truncates the aggregate text and saves full output for offset/limit reads. Its [Bash tool](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/coding-agent/src/core/tools/bash.ts) retains structured `exit_code`, output, timing and a full-output path when applicable. A nonzero command exit may resolve as structured content in Code Mode; `Promise.allSettled` fulfillment alone is not command success.

Maka [archives large model projections](https://github.com/apache/maka/blob/d6a5b99ba0f557e4bd27a5a64c4988d3cbf7f4be/packages/runtime/src/tool-result-archive-transition.ts#L235) above 7,500 UTF-8 bytes and exposes same-session continuation through Read, preserving error status. The Claude reconstruction [Bash projection](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/packages/builtin-tools/src/tools/BashTool/BashTool.tsx#L870) uses a persisted-output reference and a 2KB preview. These budgets are implementation choices, not proven optimal defaults. Capture limits remain real: Maka shell streams retain at most a 1MiB tail each, and the Claude fork caps a retained shell file at 64MB.

The private OpenPI trace contains rejected results printed as `reason: {}`. Direct JSON serialization of an Error loses its non-enumerable message; this observation does not establish that the underlying tool lacked the error. Script summaries should explicitly preserve the reason string and inspect structured status/exit code. Native serialization improvements belong to the native executor; package tools can improve their own typed feedback through existing result contracts.

**Recommendation:** filter before printing, return concise command summaries plus native evidence references, and page retained output instead of rerunning a command. OpenPI can improve its package-owned results and model guidance through native seams. Pi also has a `tool_result` hook; changing its model-facing content must deliberately preserve compatible structured content, error status and provenance. UI collapse alone saves no model context. Do not create a parallel artifact/session store or rewrite historical tool results merely to imitate another harness.

### 4. Stable prefixes matter; native cache identity is already present

Codex's [client](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/client.rs#L1496) reuses incremental WebSocket input only when non-input request properties remain compatible and the new input extends the established history. This is provider/transport state, not a general claim that all requests can send only their last message. Pi's [Responses adapter](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/ai/src/api/openai-responses.ts#L334) already derives `prompt_cache_key` from Session identity when caching is enabled.

Maka's [#5879](https://github.com/apache/maka/issues/5879) remains open, but [#5891](https://github.com/apache/maka/pull/5891), [#6028](https://github.com/apache/maka/pull/6028) and [#6029](https://github.com/apache/maka/pull/6029) merged narrower fixes: exact-name activation, Session-backend activation retention, and stable required sandbox tools. The activation map is in memory and resets on backend reconstruction. [#5925](https://github.com/apache/maka/pull/5925) removed dynamic unknown-outcome system notices while retaining paired tool results. The Claude fork's `cache_edits` path is opt-in and model/provider-gated, not a portable optimization.

OpenPI already has [cache diagnostics](https://github.com/openpi-dev/openpi/blob/625d4aae5b9b347161079dbbae62a3a5ad583852/extensions/model-info/cache-diagnostics.ts), including usage, tool/system fingerprints and explicit `verifiedCause: null`. However, its identity is sampled at [before_agent_start](https://github.com/openpi-dev/openpi/blob/625d4aae5b9b347161079dbbae62a3a5ad583852/extensions/model-info/index.ts#L118), not from every final provider payload. Within one user turn, it cannot by itself prove that all subsequent request prefixes remained identical. Pi also records tool-loadout deltas in transcript order; Session-retained loading is not a missing principle to recreate.

**Recommendation:** inspect actual per-request payload fingerprints through native hooks before changing cache behavior. Keep OpenPI-owned prompts/tool registrations stable where semantics permit. A zero cache-read observation is not proof of local invalidation; model, retention, account routing and gateway behavior can change it. WebSocket continuation or provider-specific cache editing belongs in Pi's provider layer and requires demonstrated provider support.

### 5. Retry and stream timing need separate ownership

Codex [retry handling](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/responses_retry.rs#L124) respects retry advice, configured limits and transport fallback, and emits reconnect state. Its unbounded-connection mode is feature-gated, not a recommendation. Maka [disables SDK retries](https://github.com/apache/maka/blob/d6a5b99ba0f557e4bd27a5a64c4988d3cbf7f4be/packages/runtime/src/model-adapter.ts#L404), owns replay barriers and exposes [physical-attempt telemetry](https://github.com/apache/maka/blob/d6a5b99ba0f557e4bd27a5a64c4988d3cbf7f4be/packages/runtime/src/provider-request-telemetry.ts#L652). Its current ten-attempt cap can itself create long waits; copying the number does not improve latency. [#5663](https://github.com/apache/maka/pull/5663) fixed a particular 2xx interruption classification; the broader [#4599](https://github.com/apache/maka/issues/4599) remains open and [#4600](https://github.com/apache/maka/pull/4600) closed unmerged.

The Claude reconstruction [stream watchdog](https://github.com/bug-superman/claude-code/blob/0753dafcccf433abc40a3de6abaa24ddce7d86f3/src/services/api/claude.ts#L1970) is opt-in, resets on every event and distinguishes request/header wait from later stream inactivity. Pi already owns [interruptible provider backoff](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/ai/src/utils/provider-retry.ts) with SDK retries disabled, plus Session retry/recovery lifecycle. Another OpenPI retry loop would compound those owners.

Pi exposes [request, header, response and parsed-stream hooks](https://github.com/earendil-works/pi/blob/06a466935536f8c9bcacb2d5efc0fc021be1bdff/packages/coding-agent/src/core/extensions/types.ts#L900). OpenPI can observe request start, received headers, first parsed event, last parsed event, completion, usage and native retries. A parsed-event hook cannot capture malformed bytes rejected before parsing, or reveal hidden gateway queueing/internal attempts. First parsed event and first user-visible content also differ from first network byte or first generated token.

**Recommendation:** correlate logical model requests with native attempts and gateway attempts, then fix the layer consuming the time. Raw stream validation, body-idle cancellation and safe stream replay are provider/gateway responsibilities. Long reasoning without visible text is not sufficient evidence of a dead connection. The 399s incident needs bounded gateway stream evidence; tool batching cannot remove that one upstream wait.

### 6. Background compaction is native history work and provider-dependent

Codex [asynchronous compaction](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/session/async_compaction.rs#L40) requires its feature flag, remote-compaction V2 and compatible settings. It captures history/model/auth identity, runs speculatively, validates history generation before adoption, cancels on shutdown and accounts for completed work even if discarded. Relevant [tests](https://github.com/openai/codex/blob/1b6e0d8145e1fe5b2663d32fbe7ee02f51a10e1c/codex-rs/core/src/session/async_compaction_tests.rs) cover cancellation and retained session-owned work; they were inspected, not executed here.

**Inference:** this can hide some compaction wait under useful work, but adds requests and can waste tokens. It requires native history/projection installation and recovery ownership. An OpenPI timer that calls compact earlier is not equivalent. Reducing unnecessary output is a smaller first step; native asynchronous compaction is a separate Pi proposal with generic-provider limitations.

## Recommended order and validation

| Priority | Owner | Smallest next action | Evidence required |
| --- | --- | --- | --- |
| First, alongside harness work | Gateway and Pi provider | Attribute the 399s failed response to gateway attempts, headers, stream activity and terminal parsing; expose native retry state | Exact request/attempt correlation and bounded, sanitized failure evidence |
| First OpenPI improvement | OpenPI using Pi hooks | Extend existing diagnostics to final per-request fingerprints and stage timing; measure actual tool visibility and output size | Main-call count, per-call duration, cache usage, output bytes, compaction time and failure class |
| Next | Model use and OpenPI package tools | Smaller summaries with native output references; use existing background execution for independent long work; preserve typed failure reasons | Same task/verifier succeeds; no lost error, output or extra side effects |
| Separate upstream work | Pi agent/tools | Streaming tool dispatch; resumable native shell/cells | Cancellation, malformed/truncated response, authority and replay tests, plus measured overlap benefit |
| Later, capability-dependent | Pi Session/provider | Async compaction or incremental provider continuation | History/model/auth identity, adoption/recovery tests, complete usage accounting and supported-provider evidence |

Use a frozen task/repository/verifier and the same model/thinking level for comparisons, repeat runs to expose variance, and retain failures as results. Compare high versus medium thinking separately, with the same acceptance criteria; it is not a prerequisite for the generic fixes. Report end-to-end time, model rounds, model/transport and tool intervals, compaction, cache and retries rather than only aggregate tokens or a faster single run. Do not claim an A/B result from the historical traces above.

This research adds no runtime abstraction, new provider stack, orchestration policy or configuration choice. Foreign source/tests were inspected without installing dependencies or running repository code. Runtime speed, provider compatibility and a reproduced malformed-SSE payload remain unverified by this source comparison.

Repository validation passed `bun run check` and `bun run test`: 2,516 Node tests passed with nine platform skips; all 94 UI files / 1,453 UI tests passed. Thirty pinned source-file links were checked against retained files and line bounds. These checks validate repository integration and reference shape, not the performance of the compared harnesses. Validation logs remain in the private evidence archive.
