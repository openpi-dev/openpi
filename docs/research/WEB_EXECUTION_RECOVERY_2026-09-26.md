## Sources And Findings

- Pi Web's [TerminalPanel.ts](https://github.com/jmfederico/pi-web/blob/a345b2ac363b644d5ef43b1da75b9bc53cd055c4/pi-web-plugins/terminal/TerminalPanel.ts) separates channel reconnection from terminal creation, retains output across a failed handshake, and rejects responses from old channels. Its protocol is not copied into OpenPI; the existing OpenPI PTY and offset API already owns this lifecycle.
- Maka's [chat-input-behavior.ts](https://github.com/apache/maka/blob/5b9db1ce8fdb83f0841cfd058084abe143847348/packages/ui/src/chat-input-behavior.ts) distinguishes composition from submit keys. Frozen source inspection is not live product acceptance.
- OpenPI's terminal manager owns exact Session/cwd PTYs, reuses an existing terminal on POST, and retains a detached terminal for up to 120 seconds. The UI offered only Restart after a broken connection; that operation closed the PTY, swallowed close errors, and allowed a late close receipt to rebuild a newer view.
- The native prompt route rejects trimmed text longer than 12,000 UTF-16 code units, but the UI accepted it and the rejection had no typed code. Generic transport errors could leave false preparation state; changing the draft could replace the uncertain admission identity. A rejected follow-up could also clear another running turn's projection.
- Pi emits `prompt_failed` only after admission, and `prompt_settled` also requires admission. These are exact-command handled facts, not evidence of execution success. An earlier native terminal event followed by a lost HTTP receipt must not be projected as unknown admission merely because its optimistic entry or active turn has already retired.
- Subagent file references rendered enabled buttons while the provider refused to open them. Child display cwd is a bounded presentation field, not a trusted base for parent artifact authorization. A detail remount after an action or overview round trip discarded expanded thinking and reading position.

## Interaction Design

1. **Reconnection is not restart.** Retain the XTerm and visible output. Reconnect a known terminal by exact native GET, then resume its stream at the last offset; do not create or close it. A failed initial create can retry the native idempotent create. Disable input until native readiness, drop old queued input, and never replay an uncertain write. Aborted old controllers cannot publish output, errors, or writes into a new connection.
2. **Restart is explicit and pending.** Confirm its impact on the current terminal and running processes. Cancel sends no close request; confirmation is synchronously locked, and the dialog stays pending until acknowledgment. Failure retains the old terminal identity/output and supports retry. Only a current view's close acknowledgment recreates the connection. Keep the existing Dialog mounted and drive its open state so Cancel/Escape can restore its opener. Capture confirmation focus intent before pending disables the buttons, and consume it for the exact next terminal generation after the modal closes; a newer external focus choice is not overwritten. Native close acknowledgment is not upgraded into independent OS process-exit evidence.
3. **Reject invalid text before submission without destroying it.** Share the existing native limit with the renderer and store. Count trimmed UTF-16 text consistently, retain the complete draft, and give inline feedback. A typed definite rejection retires only its own optimistic admission, not an unrelated running turn.
4. **Uncertain admission retains the original request.** Reuse the existing recovery projection and native command identity. Ordinary Send cannot silently replace it after editing. Original-request retry accepts no new payload; an explicit new send remains a separate operator choice. Exact native admission/handled evidence can resolve the old request without clearing a newer draft revision. Preserve execution failure feedback instead of treating it as an admission rejection or a successful run.
5. **Inspection preserves one owned detail.** Refresh the current child through a revision input rather than changing its React identity. Keep only the most recently selected detail mounted and hidden during an overview round trip, pause inactive reads, and unmount on child/Session changes. Local references whose provider cannot open them remain selectable text with an accurate availability tooltip, not enabled dead buttons. Parent artifact grants and explicit external-file consent are unchanged.
